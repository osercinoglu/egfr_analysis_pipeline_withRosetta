## Two prototype defects retired

**The parquet short-circuit.** `run_pipeline.py:241` returned early if a result parquet
existed, so re-running with a larger `--n_decoys` silently did nothing. `completed_decoy_ids()`
now reports exactly which decoys exist, so extending an ensemble is additive.

**The all-or-nothing checkpoint.** The prototype's `save_every_n_decoys` defaulted to 50,
equal to the usual `--n_decoys 50`, so an interruption at decoy 49 lost the entire
structure. Each shard now flushes its own part files every `flush_every` decoys and owns
them exclusively — no shared checkpoint, no lock. A test kills a writer mid-run and asserts
the flushed decoys survive.

## Design decisions worth recording

**`env_digest` deliberately excludes `cpu_count`, `platform` and `machine`.** Results must
not depend on how many cores produced them — decoy *i* is seeded `base_seed + i` — and
requiring an identical OS string would make cross-machine comparison impossible. Both are
still recorded in `env.json` as diagnostics; they are just not part of the identity.

**PyRosetta's version is read from distribution metadata, never by importing it.** A
subprocess test asserts that capturing the environment leaves `pyrosetta` out of
`sys.modules`, so the unit tier stays usable on a machine that has never installed it.

**A schema or contract version mismatch raises rather than being interpreted.** A silently
mis-read manifest is worse than no manifest.

**`assert_compatible` checks the `regeneration_key` only when a PyRosetta version is
supplied.** Otherwise a caller that cannot see Rosetta (the analysis path, deliberately)
would trip the check on an absent version rather than on a real difference.

**A test asserts no `E_ij`-like column is ever stored.** The invariant is load-bearing
enough to guard directly: storing `E_ij` would freeze the many-body formula at generation
time and undo the whole design.

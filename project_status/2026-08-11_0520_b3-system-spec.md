## Design decisions worth recording

**Two-phase validation.** `model_validate` checks shape and touches no files, so it stays
unit-testable and fast. `check_against_structure()` / `validate_against_structure()` check
against real coordinates. They collect *every* problem before raising, and name what is
actually present — a wrong chain reports the chains that exist, a wrong residue number
reports the residue range in that chain. Diagnosing a bad spec should take one run.

**Ligand identity is a PDB position, never a name prefix.** `(chain, resseq, icode)` is
unique, which fixes the prototype's `find_ligand_resnum` (`run_pipeline.py:186`) returning
the first `name3()` match — that collapsed N ligand copies to one and made cofactors
invisible.

**Autodetection includes metals and cofactors, deliberately.** `from_pdb` with no explicit
selector takes every non-water, non-standard HETATM residue as a component, because they
are nodes in the contact graph. Waters and MSE-style backbone residues are excluded.
`autodetect=False` gives protein-only from a file that contains heteroatoms.

**Coordinates are parsed from ATOM/HETATM columns directly**, not through a structure
library, for PDB files. This runs on every spec load, needs no connectivity, and must not
depend on PyRosetta. mmCIF falls back to BioPython.

## A trap found, documented, and pinned by a test

**5HG8's processed PDB says `Z34`, not its true CCD code `634`.** Stage 4 rewrites the
HETATM `resName` to the Rosetta name, so a spec built from a legacy `_clean.pdb` carries
the *Rosetta* name in `comp_id` — correct for the pose, wrong for reporting.

This is not a bug in `spec.py`; it is a property of the legacy Stage-4 output, and it is
exactly the `comp_id` / `rosetta_name` confusion the module exists to prevent, arriving
from the other direction. Recorded as a `.. warning::` on `from_pdb` and pinned by
`test_processed_pdbs_carry_the_rosetta_name_not_the_ccd_code`.

**Consequence for later steps:** when `recipes/egfr.py` generates specs for the 61
structures, the true CCD code must come from `config/ligand_overrides.yaml` or the Stage-1
inventory, with the Rosetta name going in `rosetta_name`. Building those specs by scanning
the processed PDBs alone would silently propagate `Z34` into every report.
